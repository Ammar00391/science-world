# تقرير دمج V22 على أساس V21

تاريخ العمل: 6 نوفمبر 2026

## الحالة

تم إنشاء نسخة مصدر V22 من V21 وإجراء التعديلات الموضحة أدناه. لم يتم بناء APK محليًا ولم يتم اختبار التطبيق على جهاز Android؛ بيئة العمل لا تحتوي Flutter أو Dart أو Android SDK، كما أن الاتصال بتنزيل حزم Flutter غير متاح في هذه الجلسة. لا يُعلن نجاح بناء أو اختبار Flutter قبل تشغيل CI أو بيئة Android فعلية.

## التعديلات المدمجة

1. ترقية إصدار Flutter إلى `2.2.0+22` (versionCode 22).
2. رفع `targetSdk` إلى Android API 36، وهو المستوى المطلوب للتطبيقات الجديدة والتحديثات على Google Play بدءًا من 31 أغسطس 2026.
3. إنشاء أيقونات Launcher من شعار عالم العلوم وتعيينها في AndroidManifest.
4. إزالة تشغيل صوت المقدمة تلقائيًا.
5. إضافة شخصية صغيرة مرسومة محليًا في شاشة إنشاء الحساب فقط؛ تغطي عينيها عند إخفاء كلمة المرور وتفتح عينيها عند إظهارها.
6. جعل فشل تهيئة Supabase لا يمنع تشغيل التطبيق المحلي، مع بقاء الخدمات المتصلة محمية بفحوص الإعداد.
7. حذف السعر والمدة غير المعتمدين من العرض؛ الفضي والذهبي يظهران السعر والمدة كـ«يُعلن لاحقًا» وتبقى أزرار الدفع معطلة حتى اعتماد القيم.
8. جعل صلاحيات مفاتيح الميزات غير المعروفة مغلقة افتراضيًا.
9. تعديل مخطط SQL لقبول مدة اشتراك إيجابية قابلة للضبط بدل حصرها في 30/75 يومًا، ومنع القيمة الافتراضية الصامتة في أكواد التفعيل الجديدة.
10. جعل Release build يتطلب Keystore ثابتًا، مع سماح صريح ببناء preview debug-signed عند ضبط `ALLOW_DEBUG_SIGNED_RELEASE=true`.
11. إضافة تجهيز Gradle Wrapper المفقود في بيئة CI من مشروع Flutter مؤقت، دون استبدال ملفات Android الحالية.
12. إضافة فاحص مشروع Python وGitHub Actions وتحديث Codemagic لإجراء analyze/test/build وتجهيز ملف مصدر ZIP.
13. إضافة مثبت SDK لضمان Android API 36 وBuild Tools 36.0.0 وNDK 28.2.13676358 في CI.
14. إزالة واجهات Google OAuth وفق اعتماد الدخول بالبريد وكلمة المرور.
15. إضافة شاشة تعيين كلمة مرور جديدة وربط حدث استعادة كلمة المرور من Supabase بمسار التطبيق.
16. إضافة ترحيل V22 منفصل لقاعدة بيانات Supabase الموجودة، دون إعادة تشغيل bootstrap على قاعدة الإنتاج؛ ولا يفرض الترحيل مدة تخمينية للأكواد القديمة التي لا تحمل مدة.
17. إصلاح GitHub Actions ليكتب `android/local.properties` بمساري Flutter وAndroid SDK قبل تشغيل Gradle، إذ يعتمد `settings.gradle` على وجودهما.
18. إضافة حالة `isInitialized` لـSupabase، ومنع الصفحات والخدمات من طلب `Supabase.instance.client` لمجرد أن مفاتيح الاتصال موجودة بعد فشل التهيئة.
19. توحيد تثبيت Android SDK وقبول التراخيص داخل GitHub Actions وCodemagic، وتجنب وصف بنك مجاني غير منشور بأنه متاح للطالب.

## الفحوصات التي نُفذت فعليًا

- نجح `scripts/validate_curriculum_catalog.py`: 9 مواد، 52 وحدة، 237 درسًا. هذا تحقق بنيوي وليس تصديقًا رسميًا لمحتوى كل كتاب.
- نجحت أداة `scripts/validate_question_bank.py` بنيويًا على ملفي المسودات: 6 أسئلة مجانية + 12 مدفوعة، وكلها `draft_needs_teacher_review`، مع تحذير أن العدد لا يحقق الهدف وأنها لا يجوز نشرها.
- نجح `scripts/validate_project.py`: ملفات JSON والفهرس وأصول pubspec والاستيرادات النسبية وأيقونات Android وAPI 36 وإعدادات توقيع الإصدار.
- نجح `python -m py_compile scripts/validate_project.py`.

## ما لم يُختبر أو يُنفّذ

- لم يعمل `flutter pub get` أو `flutter analyze` أو `flutter test` أو `flutter build apk --release`؛ أدوات Flutter/Dart غير مثبتة في بيئة التنفيذ.
- لم يتم تشغيل SQL على مشروع Supabase الحقيقي أو التحقق من SMTP/Storage/Edge Functions أو صلاحيات مدير الإنتاج. ملف SQL محدث فقط.
- لا يوجد APK أو AAB ناتج في هذه الحزمة.
- لم يُختبر تسجيل الدخول أو OTP أو الدفع أو تنزيل PDF أو وضع عدم الاتصال على جهاز فعلي.
- لا توجد أسئلة معتمدة أو ملخصات ومثال محلول نهائي موثّق بالصفحات؛ تبقى مسودات الأسئلة خارج أصول التطبيق.
- شخصية التسجيل مرسومة بـCustomPainter ولم تُراجع بصريًا على جهاز حقيقي.

## تفعيل بناء CI

- Codemagic/GitHub يستطيع إنتاج APK تجريبي موقّع بمفتاح debug للتثبيت والاختبار. لا تستخدمه كتوقيع إصدار دائم.
- للإصدار الرسمي يجب توفير Keystore دائم ضمن الأسرار: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `ANDROID_STORE_PASSWORD`. يجب حفظ نسخة آمنة من Keystore لدى مالك التطبيق؛ فقدانه يمنع إصدار تحديث يثبت فوق النسخة السابقة إذا لم يكن هناك Play App Signing/مفتاح بديل.
- يجب توفير `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` في بيئة CI الرسمية عند تغيير القيم الافتراضية الحالية. المفتاح publishable فقط؛ يمنع وضع `service_role` أو مفاتيح Secret في التطبيق أو المستودع.
- قبل اعتماد الإنتاج شغّل `python3 scripts/validate_project.py --production`، ثم أوامر Flutter المذكورة أدناه مع كامل اختبارات الجهاز والخدمات. سيفشل فحص الإنتاج حاليًا عمدًا لعدم وجود سؤال محلي معتمد.

## أوامر البناء في بيئة Flutter

```bash
bash scripts/prepare_android_wrapper.sh
flutter pub get
python3 scripts/validate_project.py
flutter analyze
flutter test --reporter expanded
bash scripts/prepare_release_signing.sh
flutter build apk --release
```

لمنع إطلاق محتوى ناقص، لا تعتمد النسخة النهائية حتى تُراجع الكتب الرسمية ويُعتمد محتوى البنك، ثم تنجح جميع الاختبارات السابقة واختبارات الجهاز الحقيقي.
